# KRD Manga Reader v3 — Supabase

Новая версия сайта KRD Manga Reader с постоянной базой, авторизацией, админкой и приватными страницами манги.

## Что сделано

- Вход **только по заранее зарегистрированному никнейму из списка + пароль**. Саморегистрации на сайте нет.
- **Katsuro** — администратор: создаёт, редактирует и удаляет тома, добавляет главы, меняет названия глав и страницы.
- Все остальные — читатели: читают, оставляют и удаляют **свои** комментарии, сохраняют избранное, оценки и прогресс.
- Незалогиненный посетитель видит форму входа вместо каталога/читалки.
- Страницы глав и обложки, добавленные через админку, находятся в **приватном Supabase Storage**. Политики RLS запрещают анонимное чтение и не-администраторские изменения.
- Два режима чтения, масштаб, переключение по левой/правой части страницы, закреплённая верхняя панель.
- Оценки 1–10, средняя оценка всех голосов, один голос на аккаунт (голос можно обновить).
- Звуки окружения, которые пользователь добавляет сам; проигрывание по кругу.
- 8 тем, адаптивность для телефона, планшета и ноутбука.

## Шаг 1. Создай проект Supabase

1. Зайди на https://supabase.com/dashboard и создай проект (можно Free).
2. Открой **SQL Editor → New Query**.
3. Открой файл `sql/schema.sql`, скопируй его **полностью** и нажми **Run**. Делай это в **новом проекте**, потому что SQL создаёт собственные таблицы.
4. В настройках **Authentication** отключи свободную регистрацию новых пользователей (signups), если этот переключатель доступен. Даже при ошибочно включённой регистрации RLS ниже допускает к чтению только участников таблицы `profiles`.
5. Проверь, что таблицы `profiles`, `login_names`, `volumes`, `chapters`, `pages`, `comments`, `favorites`, `ratings`, `reading_progress` появились в Table Editor.
6. Проверь, что в Storage создан приватный бакет `krd-manga`.

> RLS и GRANT включены в **один** `schema.sql`: дополнительных SQL-заплаток не требуется.

## Шаг 2. Подключи браузер

1. В Supabase открой **Project Settings → API** (в некоторых версиях **API Keys**).
2. Скопируй **Project URL** и **Publishable key** (или `anon` ключ старого вида).
3. В файле `js/config.js` замени `PASTE_SUPABASE_PROJECT_URL` и `PASTE_SUPABASE_PUBLISHABLE_KEY` на свои значения.

**Не вставляй Secret key или service_role в `js/config.js`, браузер, HTML, GitHub или публичную папку!** Publishable key безопасно хранить в браузерном коде при включённом RLS.

## Шаг 3. Создай аккаунты заранее

Нужен Node.js 20 или новее (установка из https://nodejs.org/).

1. В папке сайта открой терминал, выполни `npm install`.
2. Создай файл `.env` по образцу `.env.example` и заполни `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (**только на своём компьютере**). Секретный ключ смотри в Supabase API Keys → Secret keys / Legacy service_role.
3. Скопируй `accounts.example.json` в `accounts.json`. Для каждого читателя укажи уникальные `username`, `email` и **сложный уникальный пароль не короче 12 символов**.
4. Обязательно создай аккаунт с никнеймом **Katsuro** — скрипт назначает ему роль `admin`. Всем остальным назначает роль `reader`.
5. Выполни `npm run seed`.
6. Удали или сохрани в безопасном приватном месте `.env` и `accounts.json`. В `.gitignore` они уже исключены.

**Важно про email:** Supabase Auth требует email для входа в фоне. Пользователь видит **только никнейм**, но скрипту нужен реальный формат email. Лучше использовать адреса или домен, которыми управляешь. Не используй чужие адреса. Администратор создаёт учётные записи через Auth Admin API, подтверждение email при создании производится скриптом. **Пароли никогда не хранятся в JavaScript сайта или в таблице `login_names`.**

Скрипт повторно не меняет пароли уже существующих пользователей. Если пароль нужно сменить — сделай это через Supabase Auth администратором (или отдельным доверенным серверным скриптом).

### Почему никнеймы показываются без входа

Таблица `login_names` намеренно разрешает гостям прочитать только список ников и внутренние адреса входа. Эти данные **не секретны**. Сама библиотека и аккаунтные данные защищены отдельно.

## Шаг 4. Запусти сайт

Для запросов к Supabase и демонстрационного импорта **используй локальный HTTP-сервер**, а не открытие `index.html` двойным кликом через `file://`.

Самый простой вариант (после `npm install`):

```bash
npm run serve
```

Затем открой `http://localhost:8080` в браузере.

Можно использовать VS Code Live Server. Для публикации подойдёт статический хостинг с HTTPS, но **не** выкладывай `.env`, `accounts.json` или сервисный ключ.

После входа Katsuro увидит раздел **Админ**. Сначала создай том, потом загрузи главу (несколько JPG/PNG/WebP, отсортированных по именам). Если библиотека пустая, есть кнопка **«Импортировать демо-каталог»** — она переносит 5 демонстрационных томов и 16 глав из локальных файлов. Для демо используются повторяющиеся образцы страниц; это не настоящая манга.

## Шаг 5. Добавь звуки

Положи файлы в `assets/sounds/`:

- `rain.mp3` — дождь
- `forest.mp3` — лес
- `train.mp3` — поезд
- `fire.mp3` — камин
- `wind.mp3` — ветер
- `night.mp3` — ночная природа

Названия и пути меняются в `js/sounds.js`. Можно добавить сколько угодно треков. В читалке выбери трек и он заиграет **по кругу** (`loop`). Если файла ещё нет, пункт уже появится, но воспроизведение выдаст сообщение об ошибке. Это ожидаемо, пока не добавишь звук.

## Как работают важные ограничения

- **Читать без входа нельзя**: сайт показывает форму входа, таблицы томов/глав/страниц закрыты правилами Supabase RLS; приватные изображения скачиваются через авторизованные запросы Supabase Storage и отображаются как временные локальные blob-адреса браузера.
- Читатель не может загружать или удалять главы и не может менять роль пользователя даже через запрос к API: это запрещено на стороне базы и хранилища.
- Удалять комментарии может **только автор**; Katsuro не получает исключения для удаления чужих комментариев.
- Прогресс привязан к пользователю и главе. Для постраничного режима сохраняется выбранная страница, для вебтуна — последняя видимая.
- Избранное можно убрать повторным нажатием на сердечко как на карточке, так и на странице тома.
- Оценка тома — среднее арифметическое всех голосов (1–10); один голос на пользователя на том, с возможностью изменить голос.
- Вспомогательные демонстрационные картинки из `assets/pages/` поставляются в архиве для импорта и доступны как обычные статические файлы. **Перед публикацией, если требуется полное закрытие любых страниц для гостей, удали `assets/pages/` из публичного хостинга после демо-импорта.** Настоящие главы, загруженные в приватный Storage, не имеют этой проблемы.

## Ограничения

- Бесплатный план Supabase имеет лимиты на хранение и трафик; большие коллекции манги могут их превысить. Проект без активности может быть приостановлен на Free.
- В этом архиве нет твоих ключей/паролей и нет живого подключения к твоему аккаунту Supabase: их вводишь ты.
- Читатели должны быть онлайн, чтобы читать из базы, писать комментарии и сохранять прогресс.
- Не добавляй мангу или звуки, на публикацию которых у тебя нет прав.
- Для публичного выпуска рекомендуется дополнительно провести браузерное и нагрузочное тестирование после подключения настоящего Supabase-проекта.
